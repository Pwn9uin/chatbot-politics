# 규칙 적용 방식

[DEBATE_RULES.md](DEBATE_RULES.md)의 각 규칙을 챗봇이 어떻게 지키도록 구현했는지 정리한 문서다.

## 요약

규칙은 세 가지 방식으로 적용된다.

| 방식 | 의미 | 적용 대상 |
|---|---|---|
| **코드 강제** | 코드가 직접 막거나 통제한다. 모델이 지시를 어겨도 결과가 바뀌지 않는다. | 토론 단계 순서, 발언 차례 |
| **코드 검사 + 재작성** | 코드가 모델 출력을 검사하고, 위반이 있으면 모델에게 다시 쓰게 한다. | 완충 표현 금지 (규칙 3) |
| **지시문** | 규칙을 모델의 지시문에 넣어 따르게 한다. 코드는 결과를 확인하지 않는다. | 규칙 1의 비판적 사고 지원, 규칙 2, 4, 5, 형식 세부 사항 |

## 공통: 규칙 문서를 지시문으로 사용

- `engine.py`의 `load_rules()`가 `docs/DEBATE_RULES.md` 전체를 읽는다.
- `Debate._instructions()`가 아래 세 가지를 이어 붙여 OpenAI Responses API의 `instructions`로 보낸다.
  1. 규칙 문서 전문
  2. 이번 토론 정보: 주제, 사용자 입장, 챗봇 입장, 진행 순서표
  3. 지금 할 일(`task`): 모드와 단계에 따라 달라짐
- 모든 API 호출(토론 발언, 자료 조사, 정리)이 이 지시문을 쓴다. 완충 표현 재작성 호출만 예외다.
- 규칙 문서를 수정하면 다음 호출부터 바로 반영된다. 코드를 고칠 필요가 없다.

## 규칙별 적용 방식

### 규칙 1. 토론 형식 준수와 비판적 사고 지원

| 항목 | 방식 | 구현 |
|---|---|---|
| 단계 순서 | 코드 강제 | `debate_format.py`의 `STEPS`에 10단계와 발언자를 고정했다. `Debate.step_index`가 현재 단계를 추적한다. |
| 발언 차례 | 코드 강제 | `submit_user()`는 사용자 차례가 아니면 예외를 낸다. `advance_bot()`은 사용자 차례가 올 때까지 챗봇 발언만 생성한다. |
| 형식 명시 | 코드 + 지시문 | 화면 사이드바에 전체 순서와 현재 단계를 표시한다. 사용자 차례에는 단계의 할 일과 권장 분량을 안내한다. 챗봇 발언 첫 줄에 `[단계명 \| 입장]`을 쓰도록 지시한다. |
| 단계별 범위·분량 | 지시문 | `_bot_speech()`가 단계의 `guide`(할 일)와 `length`(분량)를 지시문에 넣는다. |
| 사용자 형식 위반 지적 | 지시문 | 직전 사용자 발언이 단계 범위를 벗어났으면 첫머리에서 지적하라고 지시한다. |
| 비판적 사고 지원 | 지시문 | 규칙 문서 제3장에 따라 숨은 전제, 논리적 비약, 근거와 결론의 간극을 지목하게 한다. |

### 규칙 2. 동조 금지와 최강 반론

- **방식:** 지시문
- **구현:** 규칙 문서 제4장, 그리고 `_bot_speech()`의 지시 "상대 주장에 동조하지 말고 가장 강한 반론·반례를 제시한다"

### 규칙 3. 완충 표현 제한

- **방식:** 지시문 + 코드 검사·재작성
- **구현:**
  1. 규칙 문서 제5장과 `_bot_speech()`의 지시로 완충 표현을 쓰지 말라고 한다.
  2. 발언이 생성되면 `find_cushions()`가 `CUSHION_PATTERNS`(제5장 3항의 금지 표현을 정규식으로 옮긴 목록)로 검사한다.
  3. 금지 표현이 발견되면 `_remove_cushions()`가 모델을 한 번 더 호출해 해당 표현만 고쳐 쓰게 한다. 이때 주장, 근거, 등급 표기, 출처는 유지하도록 지시하고 웹 검색은 쓰지 않는다.
- **적용 범위:** 토론 단계의 챗봇 발언에만 적용한다. 자료 조사와 정리 단계 결과는 검사하지 않는다.
- **`[불확실]` 표기:** 근거 수준을 서술하는 것이므로 완충 표현으로 보지 않는다(제5장 5항).

### 규칙 4. 공정성과 근거 수준 구분

| 항목 | 방식 | 구현 |
|---|---|---|
| 역할로 배정된 입장 | 지시문 | 지시문에 "챗봇: ○○측 (역할로 배정된 입장)"을 명시한다(제1장). |
| 근거 등급 표기 | 지시문 | `_bot_speech()`가 6개 등급(`[법령]` `[공식통계]` `[학술]` `[언론]` `[주장]` `[불확실]`) 중 하나만 쓰고 새 등급을 만들지 않도록 지시한다. |
| 출처 확인 | API 기능 | 모든 토론·자료·정리 호출에 OpenAI `web_search` 도구를 켠다(지역은 한국). 응답의 `url_citation` 주석을 `llm._collect_sources()`가 모아 화면에 출처로 보여 준다. |
| 정리 단계의 중립성 | 지시문 | `run_review()`가 "중립적 진행자, 승패 판정 금지"로 모드를 바꾸고 제9장의 네 항목을 작성하게 한다. |

### 규칙 5. 동일한 근거·논리 기준 적용

| 항목 | 방식 | 구현 |
|---|---|---|
| 발언 전 자체 점검 | 지시문 | `_bot_speech()`가 제7장 3항의 점검을 수행하되 점검 과정은 출력하지 말라고 지시한다. |
| 정리 단계 대칭 평가 | 지시문 | `run_review()`가 챗봇 근거도 사용자 근거와 같은 기준으로 평가하고 약점을 빠짐없이 지적하라고 지시한다. |

## 모드별 입력 구성

| 모드 | 함수 | `input`으로 보내는 내용 | 웹 검색 |
|---|---|---|---|
| 토론자 | `_bot_speech()` | 지금까지의 발언 기록 + 이번 단계 발언 요청 | 사용 |
| 자료 조사 | `request_research()` | 발언 기록 + 사용자의 자료 요청 | 사용 |
| 정리 | `run_review()` | 발언 기록 + 사용자가 받은 자료 목록 + 정리 요청 | 사용 |
| 완충 표현 재작성 | `_remove_cushions()` | 원래 발언 + 발견된 금지 표현 | 사용 안 함 |

- 발언 기록(`_transcript_messages()`)에서 사용자 발언은 `user`, 챗봇 발언은 `assistant` 역할로 들어간다.
- **자료 요청 결과는 토론자 모드의 입력에 넣지 않는다.** 상대 토론자인 챗봇이 사용자의 준비 자료를 미리 보지 못하게 하기 위해서다(제8장 4항). 정리 모드에서만 평가에 쓴다.

## 한계

- **지시문 의존:** 지시문으로만 적용한 규칙(2, 4, 5와 형식 세부)은 코드가 결과를 검증하지 않는다. 모델이 지시를 어기면 그대로 출력된다.
  - 예: 테스트에서 모델이 규칙에 없는 `[국제기구 보고서]` 등급을 만들었다. 이후 지시문에 6개 등급만 쓰라는 문장을 추가했지만, 코드로 검사하지는 않는다.
- **완충 표현 검사:**
  - `CUSHION_PATTERNS`에 없는 표현은 잡지 못한다.
  - 재작성 결과는 다시 검사하지 않는다.
- **분량:** 분량은 지시만 할 뿐 글자 수를 검사하지 않는다.
- **사용자 발언:** 사용자 발언의 형식 위반은 코드가 막지 않는다. 챗봇이 다음 발언에서 지적하고 정리 단계에서 평가하는 방식에 맡긴다.

## 보강할 수 있는 방법

| 방법 | 효과 | 비용 |
|---|---|---|
| 등급 표기 검사 | `[...]` 표기가 6개 등급 밖이면 재작성 | 위반 시에만 추가 호출 |
| 분량 검사 | 단계별 글자 수 범위를 크게 벗어나면 재작성 | 위반 시에만 추가 호출 |
| 재작성 결과 재검사 | 완충 표현이 남으면 한 번 더 재작성 | 위반 시에만 추가 호출 |
| 검수 모델 단계 | 별도 호출로 규칙 2·4·5 위반 여부를 판정하고 위반 시 재작성. 정규식으로 잡을 수 없는 규칙에 유일하게 쓸 수 있는 방법 | 매 발언마다 추가 호출 |
